## 一、Critical（P0）

### A-2026-0628-C1. 安卓 cleartext 流量被 OS 默认阻断 — FTP/HTTP WebDAV 静默失败 [ ]
- **位置**：`app-android/src/main/AndroidManifest.xml:8-12`
- **问题**：`targetSdk=36` 默认 `usesCleartextTraffic=false`。`AddServerScreen.kt:166,175` 的 cleartext 警告 UI 假设连接会成功，但实际 FTP（非 FTPS）与 HTTP WebDAV 在系统层就被拒绝，无诊断。
- **影响**：用户配置无 TLS 的服务器后只看到"连接失败"，无法诊断也无法绕过。
- **修复**：添加 `android:usesCleartextTraffic="true"` 或实现 `network_security_config.xml` per-host 白名单。

### A-2026-0628-C2. 桌面端命令行/拖入的文件参数在 App 订阅前就被丢弃 [ ]
- **位置**：`app-desktop/src/desktopMain/.../Main.kt:264-266` + `ui-compose/.../App.kt:124-128`
- **问题**：`composePanel.setContent { App(...) }` 异步调度；`Main` 紧接着同步 `dropEvents.tryEmit(initialFile)`。`dropEvents = MutableSharedFlow(extraBufferCapacity=4)` 且 `replay=0`，无订阅者时事件直接丢弃，`App` 内的 `LaunchedEffect(flows.dropFilePath)` 来不及订阅。
- **影响**：从资源管理器"打开方式 → WindPlayer"的文件静默失败。重大用户功能损坏。
- **修复**：`dropEvents` 用 `MutableSharedFlow(replay = 1)`，或让 `App` 用 `LaunchedEffect(Unit)` 主动拉取暂存的初始路径。

### A-2026-0628-C3. FTP 用户开启 TLS 但播放路径永远是明文 [ ]
- **位置**：`core-vfs/.../desktopMain/VfsManager.kt:141-146` + `jvmShared/FtpClient.kt:100-111`
- **问题**：H18 给 FTPS 加了 TLS 支持，但仅覆盖 `FtpClient` 内部的目录列举连接。播放时 `preparePlayback` 调 `client.resolveUrl(path)` 返回硬编码 `ftp://user:pass@host/path`，mpv 用自己的 FTP 客户端打开此 URL 时**无 TLS**。
- **影响**：完全否定用户的"use TLS"选项；攻击者嗅探到明文密码与视频流，UI 还显示已加密。配合 C1 在 Android 上更严重。
- **修复**：FTP `useTls=true` 时通过 StreamProxy 转发（同 SFTP）；或彻底放弃 FTP 流式播放；至少要硬警告。

### A-2026-0628-C4. 桌面端 `themeMode` 完全未持久化（阶段 51 回归） [ ]
- **位置**：`app-desktop/.../DesktopPersistence.kt:70-99`（同样问题在安卓 `SettingsHelper.kt:9-30`）
- **问题**：`PlayerSettings.themeMode` 字段已加但 `loadSettings`/`saveSettings` 都不读写该 key。
- **影响**：用户选择的浅色/深色每次启动都重置回 `SYSTEM`；`MainActivity.onCreate` 闪一帧错误调色板。
- **修复**：`props.setProperty("themeMode", settings.themeMode.name)` + 反序列化用 `runCatching { ThemeMode.valueOf(it) }.getOrNull() ?: ThemeMode.SYSTEM`。

### A-2026-0628-C5. SAF 仅持久化 READ 权限 — 重启后所有本地文件写操作失败 [ ]
- **位置**：`app-android/.../SafHelper.kt:26-33`
- **问题**：`takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)` 只持久化 READ。首次会话靠 launcher 即时授予的 WRITE 工作；重启后 rename/delete/copy/move 全部静默失败。
- **影响**：用户重启后失去所有本地文件管理功能，无错误提示。
- **修复**：`FLAG_GRANT_READ_URI_PERMISSION or FLAG_GRANT_WRITE_URI_PERMISSION`。

### A-2026-0628-C6. SAF/DocumentFile I/O 跑在主线程 — ANR 风险 [ ]
- **位置**：`app-android/.../FileBrowserScreen.kt:127-152, 279, 320-321, 358-360`
- **问题**：`rootDoc.listFiles()` / `createFile` / `input.copyTo(output)` / 删除 / 重命名全在 `rememberCoroutineScope()`（Main 调度器）执行；只有后续 refresh 才走到 IO。
- **影响**：慢速 provider（Google Drive / USB-OTG）触发 ANR。
- **修复**：每个操作体包 `withContext(Dispatchers.IO) { ... }`。

### A-2026-0628-C7. 桌面端 `audio-add` 在 `loadfile` 之前发出 — 外挂音轨永远丢失 [ ]
- **位置**：`ui-compose/.../desktopMain/PlayerScreen.kt:260-266`
- **问题**：`LaunchedEffect(initialFilePath)` 先发 `audio-add` 再发 `loadfile`。mpv 的 `audio-add` 要求有活动文件，无文件时静默失败。
- **影响**：`VfsManager` 匹配到的所有外挂音轨（含阶段 7 的双路串流设计）实际上从未挂载。整个外挂音轨功能在桌面端失效。
- **修复**：参照字幕模式（`:136-143`）把 `audio-add` 推迟到 `MpvEvent.FileLoaded` 处理器。

### A-2026-0628-C8. 桌面端启动时 `defaultVolume` 完全未应用 [ ]
- **位置**：`app-desktop/.../Main.kt:181-189`
- **问题**：`windowOpened` 设置 `wid/vo/hwdec/keep-open/idle/sub-font-size/sub-border-size` 但**从不**设置 `volume`；`applyMpvSettings` 仅在 `onSettingsChanged` 时调用，启动时不调。
- **影响**：用户在设置里把默认音量改成 50% 完全无效，每次启动都是 mpv 默认的 100%（耳机用户伤害巨大）。
- **修复**：`player.initialize()` 前后调一次 `applyMpvSettings(player, settingsState)`，或单独 `setOption("volume", ...)`。
