## 三、新发现 — Medium 严重程度

### SEC-1. `servers.properties` 缺少 0600 文件权限
- **位置**：`core-vfs/src/desktopMain/kotlin/dev/windplayer/vfs/VfsManager.kt:319`
- **问题**：`saveConfig()` 用 `FileOutputStream.use { ... }` 写入但未设权限。`KnownHostsManager.kt:67-77` 显式把 `known_hosts` chmod 0600，但 `servers.properties`（包含 host、username、非 Windows 下的明文密码）落到默认 umask（POSIX 下 0644，world-readable）。
- **影响**：本地其他用户可读取服务器列表与（Linux/macOS 下的）明文密码。
- **修复**：把 `KnownHostsManager` 的 `restrictFilePermissions` helper 抽到共享 internal util，写完 `servers.properties` 后调用一次。
- **状态**：`[x]`

### SEC-2. WebDAV 默认走明文 HTTP，泄漏 Basic Auth 凭据
- **位置**：`core-vfs/src/commonMain/kotlin/dev/windplayer/vfs/ServerConfig.kt:37-42`
- **问题**：`httpScheme()` 当用户输入裸主机名（无 `http(s)://` 前缀）且端口非 443 时返回 `"http"`。`WebdavClient.connect()` 会把 `Authorization: Basic <base64(user:pass)>` 通过明文 HTTP 发出。FTP 端 UI 默认 `useTls=true`（A-2026-H18），WebDAV 没有同等保护。
- **影响**：被动网络攻击者（咖啡店 Wi-Fi）可收割 WebDAV 凭据。
- **修复**：把 `httpScheme()` 的兜底分支改为 `"https"`，要求用户显式输入 `http://` 才走明文；显式 port 80 仍走 http。
- **状态**：`[x]`

### SEC-3. WebDAV `downloadFile` 把整个文件载入内存
- **位置**：`core-vfs/src/jvmShared/kotlin/dev/windplayer/vfs/WebdavClient.kt:128-129`
- **问题**：`response.body()` 全量读入 `ByteArray` 再 `writeBytes`。`VfsManager.downloadSubtitle` 走这条路径，恶意/被攻陷的 WebDAV 服务器或一次误点可触发 OOM。
- **影响**：远程 OOM 拒绝服务。
- **修复**：改用 `bodyAsChannel()` + 64KB 缓冲流式写入。
- **状态**：`[x]`

### SEC-4. 全局 `usesCleartextTraffic="true"` 无 per-host 例外
- **位置**：`app-android/src/main/AndroidManifest.xml:16`
- **问题**：本地 `127.0.0.1` StreamProxy 需要它，但当前设置同时允许所有远程主机走明文（放大 SEC-2）。
- **影响**：app 范围 baseline 被弱化，掩盖 SEC-2。
- **修复**：新增 `network_security_config.xml`，默认拒绝明文，白名单 `127.0.0.1`/`localhost`。
- **状态**：`[x]`

### CON-1. Android `StreamProxy` worker 线程非 daemon
- **位置**：`core-vfs/src/androidMain/kotlin/dev/windplayer/vfs/StreamProxy.kt:33,38`
- **问题**：`Executors.newCachedThreadPool()` 默认线程工厂 + `Thread(...).start()` 都不是 daemon。桌面端（`:24-26`）则用 daemon ThreadFactory。
- **影响**：进程生命周期泄漏；与 H4 修复目标相悖。
- **修复**：与桌面端对齐，传 daemon ThreadFactory；accept 线程 `isDaemon = true`。
- **状态**：`[x]`

### CON-2. `MobilePlayerScreen.onDispose` 主线程做 SSH I/O
- **位置**：`app-android/src/main/kotlin/dev/windplayer/MobilePlayerScreen.kt:418-423`
- **问题**：`DisposableEffect.onDispose` 在 Main（Applier）线程同步执行 `currentPfd?.close()` + `streamProxy.closeSession(id)` + `streamProxy.stop()`，后者会触发 `ssh.disconnect()`，sshj 默认 socket 超时可能很长。
- **影响**：SFTP 播放退出时 ANR；debug 构建 StrictMode `NetworkOnMainThreadException`。
- **修复**：把 cleanup 包进独立 `CoroutineScope(SupervisorJob() + Dispatchers.IO).launch { ... }`。
- **状态**：`[x]`

### CON-3. `MpvRenderView` 中 `surfaceValid` TOCTOU
- **位置**：`app-android/src/main/kotlin/dev/windplayer/MpvRenderView.kt:73-77`
- **问题**：检查 `surfaceValid.get()` 与 `player.attachSurface(holder.surface)` 之间无同步，且二者跨线程（IO 协程 vs Main 的 surfaceCreated/Destroyed）。
- **影响**：mpv 绑定到已拆除的 Surface，触发"有声音无图像"或原生 surface-error。
- **修复**：把 `attachSurface` + `initialize` 放回 Main 线程（`withContext(Dispatchers.Main)`）。
- **状态**：`[x]`

### ARCH-3. `commonTest` 引用了 `jvmShared` 符号
- **位置**：`core-vfs/src/commonTest/.../TrackMatcherTest.kt:77` 用 `FileNodeComparator`（位于 `jvmShared/VfsUtils.kt:47`）
- **问题**：`commonTest` 应只测 `commonMain`。当前因 desktop+android 都继承 jvmShared 所以能编译，但一旦加 iOS/JS target，commonTest 编译立即断。
- **修复**：把 `FileNodeComparator`（纯 `Comparator<FileNode>`，无 JVM 依赖）从 `VfsUtils.kt` 拆到 `commonMain/FileNode.kt`。
- **状态**：`[x]`

### ARCH-4. `MobilePlayerScreen` 参数爆炸（15 个参数）
- **位置**：`app-android/src/main/kotlin/dev/windplayer/MobilePlayerScreen.kt:59-75`
- **问题**：15 个参数。阶段 37/38 把桌面端 `PlayerScreen` 减到 8 个，Android 端没跟上。
- **影响**：调用点 50 行参数块；新增字段要改所有 call site。
- **修复**：留作独立重构任务（影响 call site 较多）。
- **状态**：`[!]`
