## 二、Critical

### C1. Desktop Release ZIP 不可作为声明的跨平台发行包 `[x]`

- 位置：`app-desktop/build.gradle.kts:18,44`、`.github/workflows/release.yml:32,80-92`
- `compose.desktop.currentOs` 只打包当前 runner 的本机运行时；Release 只在 Linux 构建，却使用无平台标识的 `desktop.zip` 名称。
- 启动参数写入 runner 工作区的绝对 `lib/mpv-dev` 路径，用户机器上不存在。
- 仓库只提供 Windows `libmpv-2.dll`，Linux 产物没有对应 `libmpv.so`。
- 修复：改为 Desktop 平台矩阵；运行时用发行目录相对路径或系统库搜索；产物明确标注 OS；CI 校验 ZIP 内容和启动脚本。

### C2. Android Release 发布 debug APK，无法保证升级与身份一致 `[x]`

- 位置：`.github/workflows/release.yml:70-76,88-102`
- workflow 执行 `assembleDebug`，不同 runner 的 debug keystore 可能不同，后续 tag 无法覆盖安装。
- 修复：使用 GitHub Secrets 注入 release keystore，执行 `assembleRelease`；缺少签名配置时失败，不发布伪正式 APK。

### C3. Android 全局 JNI player 的旧销毁可破坏新实例 `[x]`

- 位置：`core-mpv/.../MPVLib.kt:8-20`、`MpvPlayer.android.kt:13,119-178`、`MobileApp.kt:46,322-329`
- JNI API 没有 handle，是进程级单例；`MpvPlayer` 的锁却是实例级。
- 页面退出异步 `dispose()` 后立即允许重新打开，新 create/init 可与旧 destroy 交错。
- 影响：黑屏、命令丢失、observer 串线或 native 崩溃。
- 修复：在 Kotlin 层建立进程级生命周期协调器和 generation；新初始化等待旧 teardown 完成。长期方案是 JNI 使用实例 handle。

### C4. Android 多个 `resolveAndLoad` 可并发修改同一播放器资源 `[x]`

- 位置：`MobilePlayerScreen.kt:156-303,520-531,628-640,670-691,906,921,1136`
- EOF、手动切换、播放列表、Surface 恢复均可独立发起加载。
- 并发请求会互相关闭 PFD / StreamProxy session、覆盖字幕状态并乱序调用 `loadfile`。
- 修复：单一 `loadJob` + generation + `Mutex`；所有入口统一进入串行播放状态机。

## 三、High

### H1. Desktop PlayerScreen collector 捕获过期播放参数 `[x]`

- 位置：`ui-compose/.../PlayerScreen.kt:101-250`
- collector 只以 `player` 为 key，却捕获当前索引、列表、字幕、恢复位置和 callbacks。
- player 不变时切到下一集，后续事件仍使用第一集参数。
- 修复：使用 `rememberUpdatedState` 或显式 playback generation，并为连续三集自动播放补测试。

### H2. Desktop dispose 超时后仍销毁活跃 native context `[x]`

- 位置：`core-mpv/.../MpvPlayer.desktop.kt:108-128`
- `join(2000)` 超时只记录警告，仍执行 `mpv_terminate_destroy`，事件线程可能 use-after-free。
- 修复：绑定 `mpv_wakeup()`；先停止、唤醒并确认线程退出，再销毁 context。

### H3. Android EndFile reason 仍由状态推断 `[~]`

- 位置：`MpvPlayer.android.kt:53-95`、`MPVLib.kt:55`
- 历史 `Issues.md` P0-4 标为已修复，但 JNI 回调仍只有 event ID。
- 已加载后的解码/网络错误会被误报 STOP，QUIT/REDIRECT 无法表达。
- 修复：需要更新 `libplayer.so` 桥接层，回传 `reason` 和 `error`；在此之前文档不得标记为已彻底修复。
- 状态：Kotlin 协议、Desktop 结构解析和 native patch 已完成。已通过 GitHub Actions 以固定 mpv-android/mpv/FFmpeg/NDK 构建并替换 arm64 `libplayer.so`，产物 SHA-256 为 `ec2178cdb3b5da5da2f2375c97851d6e567a32ca640625a2301667b5fbf7f78a`。仍需在真机覆盖 EOF/STOP/ERROR/QUIT/REDIRECT，完成运行时闭环。构建说明见 `tools/mpv-android-bridge/README.md`。

### H4. Desktop property event JNA ABI 解释错误 `[x]`

- 位置：`MpvPlayer.desktop.kt:73-93`
- `MPV_FORMAT_STRING` 的 data 是 `char **`，当前少解引用一级；结构偏移还硬编码 x86_64。
- 修复：使用 JNA `Structure` 映射 `mpv_event_property`，由 JNA 计算布局。

### H5. SharedFlow 不能保证控制事件不丢失 `[x]`

- 位置：Desktop / Android `MpvPlayer` 的 `_events` 定义。
- `replay=0 + DROP_OLDEST` 在无订阅者或突发属性事件时仍会丢 `FileLoaded/EndFile`。
- 修复：控制事件使用可靠 channel/独立 flow；属性状态按名称合并或使用 StateFlow。

### H6. Android attachSurface 失败仍继续标记初始化完成 `[x]`

- 位置：`MpvPlayer.android.kt:128-137`、`MpvRenderView.kt:90-96`
- attach 异常被吞掉，调用方仍 initialize 并触发加载，形成有声无画且难以重试。
- 修复：返回成功状态或抛出异常，成功后才推进初始化状态。

### H7. FTPS 未启用证书主机名验证 `[x]`

- 位置：`core-vfs/.../FtpClient.kt:31-38`
- Commons Net `FTPSClient` 默认不做 endpoint identification。
- 修复：连接前 `setEndpointCheckingEnabled(true)`，补错误主机名证书测试。

### H8. WebDAV 将错误状态当成功并可保存错误页 `[x]`

- 位置：`WebdavClient.kt:48-63,77-103,122-142`
- connect 只拒绝 401；PROPFIND/GET 未建立成功状态白名单。
- 修复：PROPFIND 只接受预期 DAV 状态，GET 只接受成功状态；临时文件下载后原子替换。

### H9. AI 字幕完成事件未绑定源视频 `[x]`

- 位置：`TranslateService.kt:57-82`、`TranslationManager.kt:170,243`、`MobilePlayerScreen.kt:558-600`
- 视频 A 的任务完成时可能把字幕挂到正在播放的视频 B。
- 修复：请求携带 task ID、规范化 source identity 和 playback generation，消费前严格匹配。

### H10. Release workflow 的第三方 Actions 未固定 SHA `[x]`

- 位置：`.github/workflows/release.yml:37,43,49,64,95`、`.github/workflows/ci.yml`
- Release token 有 `contents: write`，可移动 tag 增加供应链劫持风险。
- 修复：所有 Actions 固定完整 commit SHA，并用注释保留可读版本号。

## 四、Medium

### M1. WebDAV PROPFIND 全量读取并构建 DOM `[x]`

- 位置：`WebdavClient.kt:98,168-200`
- 超大响应可造成远程 OOM。
- 修复：增加 8 MiB 响应硬上限和超时；仍使用加固 DOM，但远程 OOM 路径已被封闭。

### M2. Android HistoryStore 并发读改写会丢字段 `[x]`

- 位置：`HistoryStore.kt:49-119`、`MobileApp.kt:304-320`
- 多个 IO coroutine 基于同一旧快照写回，位置、轨道和缩略图会互相覆盖。
- 修复：进程级 Mutex/actor，或迁移 DataStore/Room 事务。

### M3. AI API Key 明文存储 `[x]`

- 位置：`TranslationConfigHelper.kt:20-45`
- 修复：使用 Android Keystore / EncryptedSharedPreferences，并迁移旧值。

### M4. AI 音频转换为整段 FloatArray，长视频可 OOM `[x]`

- 位置：`AudioExtractor.kt`、`WhisperEngine.kt`、`TranslationManager.kt`
- 修复：音频现在流式写入 16 kHz mono float PCM 临时文件；Whisper 每次读取 120 秒窗口、重叠 10 秒并合并时间轴。单个 FloatArray 约 7.32 MiB，长视频不再截断到 10 分钟。

### M5. TrackMatcher 前缀与剧集规则会误挂轨道 `[x]`

- 位置：`TrackMatcher.kt:45-99`
- 清除分隔符后裸 `startsWith`；结构化匹配只比较集数；`S01E01` 会退化成 `EP001`。
- 修复：明确解析标题/季/集/语言标签，音轨使用更严格规则。

### M6. StreamProxy open 中途失败泄漏 SSH 资源 `[x]`

- 位置：Desktop `StreamProxy.kt:191-205`、Android 对应 `open()`。
- 局部资源全部成功后才转移到字段，异常时 `close()` 无法看到它们。
- 修复：失败路径逆序关闭，成功后再转移所有权。

### M7. 手动 SFTP 轨道丢失 StreamProxy session ID `[x]`

- 位置：`TrackSelectionSheet.kt:270-285`、`VfsManager.kt:137-153`
- 只保留 stream URL，无法在轨道移除或退出时释放 SSH session。
- 修复：返回并持有可关闭资源句柄。

### M8. 辅助字幕缓存键跨服务器/目录碰撞 `[x]`

- 位置：Desktop `VfsManager.downloadSubtitle`、Android `MobileVfsManager.downloadAuxFile`。
- 缓存键只使用消毒文件名，多个 `English.srt` 会错误复用。
- 修复：使用 server ID + 规范化路径哈希，并校验 size/mtime。

### M9. 同一服务器并发 connect 可覆盖并泄漏旧 client `[x]`

- 位置：`VfsManager.kt:72-82`
- 修复：按 server ID single-flight/Mutex，替换时关闭旧 client。

### M10. SAF 历史项没有可靠保存实际 tree URI `[x]`

- 位置：`MobileApp.kt:296-310`、`SafHelper.kt`、`LocalFolderStore.kt`
- 历史恢复常退化为单文件播放，无法重建同目录列表。
- 修复：从实际 LocalFolder 保存 tree URI，不依赖未维护的全局 tree URI。

### M11. Android 生命周期恢复覆盖用户手动暂停状态 `[x]`

- 位置：`MobilePlayerScreen.kt:389-407`
- ON_PAUSE 总是暂停，ON_RESUME 对本地文件总是播放。
- 修复：记录进入后台前是否正在播放，仅恢复生命周期导致的暂停。

### M12. Android 远程重命名允许路径分隔符与 `..` `[x]`

- 位置：`ServerBrowseScreen.kt`、`MobileVfsManager.kt:91-97`
- 修复：UI 与 VFS 层都验证单个 basename，拒绝分隔符、控制字符、`.` 和 `..`。
