## 一、Critical（P0）

### A-2026-C1. 桌面端 `MpvPlayer` 完全没有锁，跨线程调用 mpv [ ]
- **位置**：`core-mpv/src/desktopMain/.../MpvPlayer.desktop.kt:99-157`
- **问题**：Android 端每个 mpv 调用都 `synchronized(lock)`，桌面端 **0 个 synchronized**。但桌面端 mpv 调用来自至少两个线程：Swing EDT（`DesktopShortcuts`、`CanvasMouseController`、`LayoutManager`）+ Compose UI 线程（`PlayerScreen.kt:139/148/264`）。AGENTS.md 自称 "mpv 通信必须串行化"，桌面端违反此契约。
- **影响**：mpv client API 大体线程安全但项目自身不变量要求串行化；未来非线程安全的调用组合（如某些 mpv 构建下 `mpv_wait_event` 与 property read 冲突）会暴露。
- **修复**：在 `MpvPlayer.desktop.kt` 加 `private val lock = Any()`，所有 command/setProperty/getProperty/observeProperty 包 `synchronized(lock)`，与 Android 端对齐。

### A-2026-C2. `handle` / `running` 非 `@Volatile`，跨线程不可见 [ ]
- **位置**：`MpvPlayer.desktop.kt:13-15`
- **问题**：事件线程读 `running` 决定是否继续循环；调用线程在 `dispose()` 中写 `running=false` 并清零 `handle`。无 `@Volatile` → 无 happens-before，JIT 可能缓存读。
- **影响**：**事件线程在 dispose 后继续 `mpv_wait_event` 已销毁的上下文 → 原生崩溃**；事件线程永不退出（资源泄漏）。
- **修复**：`@Volatile private var handle`、`@Volatile private var running`。

### A-2026-C3. `dispose()` 不 join 事件线程 → use-after-free [ ]
- **位置**：`MpvPlayer.desktop.kt:91-97`
- **问题**：`dispose()` 立即 `mpv_terminate_destroy` 然后清零 `handle`，事件线程仍在循环中。mpv 文档明确禁止 `terminate_destroy` 后调用任何 API。
- **影响**：每次播放器 teardown 都有定时序竞态导致原生崩溃（快机器上常错过）。
- **修复**：`running=false; eventThread?.join(2000); eventThread=null; lib.mpv_terminate_destroy(...)`（`terminate_destroy` 会唤醒阻塞的 `wait_event`，join 会快速返回）。

### A-2026-C4. Android `inferEndFileReason` 在 `synchronized(observers)` 内回调 JNI → 死锁风险 [ ]
- **位置**：`MpvPlayer.android.kt:43` 调用 `inferEndFileReason` →`:65` `MPVLib.getPropertyString`，而 dispatch 处于 `MPVLib.kt:45 synchronized(observers)`
- **问题**：JNI 事件线程持有 `observers` 监视器后，同步再入 `libplayer.so` 的 `getPropertyString`。若 `libplayer.so` 内部对该调用与 `removeObserver`/event 线程同步，构成锁顺序倒置。
- **影响**：EOF 时死锁 → 播放冻结 / ANR / Android 软重启。
- **修复**：`MPVLib.event()` 与 `eventProperty()` 改为 `synchronized(observers) { observers.toList() }` 然后**锁外**遍历副本。

### A-2026-C5. `StreamProxy.StreamSession.close()` 与 `read()` 竞态 [ ]
- **位置**：`core-vfs/src/desktopMain/.../StreamProxy.kt:165-176`（`read()` 是 `@Synchronized`，`close()` 不是）
- **问题**：`close()` 在 `releasePlayback` 或换文件时被调用，handler 线程仍在 `read()` 中。`close()` 直接 null 掉 `remoteFile/sftp/ssh` 并 disconnect → 下一次 read 触发已释放资源访问。
- **影响**：`IllegalStateException` / 原生崩溃；切换文件/退出播放时尤其明显。
- **修复**：`close()` 也加 `@Synchronized`；先 close 引用副本再 null 字段。

### A-2026-C6. WebDAV PROPFIND XML 解析器 XXE 漏洞 [ ]
- **位置**：`core-vfs/src/jvmShared/.../WebdavClient.kt:121-141`
- **问题**：`DocumentBuilderFactory.newInstance()` 未禁用 DOCTYPE / 外部实体。恶意/被攻陷 WebDAV 服务器可返回 `<!DOCTYPE foo [<!ENTITY x SYSTEM "file:///etc/passwd">]>` 触发本地文件读取、SSRF、billion-laughs DoS。文件名等文本最终被显示在 UI 上。
- **影响**：本地文件泄漏、SSRF、DoS。
- **修复**：禁用 DOCTYPE、external-general-entities、external-parameter-entities、load-external-dtd；或解析前正则拒绝 `<!DOCTYPE`。
